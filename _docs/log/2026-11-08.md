## Grooming of #4

### What was done
- PM grooming of #4 (registration, login, logout) for the split: contract operations `register`, `login`, `logout`, `getMe` with a `bearerAuth` scheme; backend rules; frontend pages and cookie; tests per layer. Swapped `backlog` for `groomed`, posted a "Groomed" comment.

- Updated `_docs/plan.md` section 5 (auth details) and `HANDOFF.md`.

### Decisions made (and why)
- Password hashing with stdlib `hashlib.scrypt`: no new dependency.
- Opaque tokens from `secrets`, stored hashed in `auth_tokens` (migration `0002`), 7-day expiry, revoked on logout: revocable sessions without a signing library.
- The cookie holds the opaque token (`HttpOnly`, `SameSite=Lax`, `Secure` outside local) instead of a signed cookie: an opaque token needs no signing. Plan updated.
- Usernames trimmed and lowercased; same 401 for unknown user and wrong password: case-insensitive uniqueness, no username enumeration.
- 422 responses must not echo the password: FastAPI's default does.
- UI in Spanish: the default categories are Spanish.
